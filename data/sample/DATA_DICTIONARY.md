# `paysim_sample.csv` data dictionary

Synthetic mobile-money transaction data, schema-compatible with the [PaySim](https://www.kaggle.com/datasets/ealaxi/paysim1)
dataset. Generated by [`scripts/generate_paysim_sample.py`](../../scripts/generate_paysim_sample.py) — see that file's
module docstring and [ADR-0004](../../docs/adr/0004-paysim-over-amlsim.md) for why this project generates rather than
downloads the source data. Fully synthetic; no production or personal data.

| Column | Type | Description |
|---|---|---|
| `step` | int | Simulated hour, 0–743 (31 simulated days × 24 hours) |
| `type` | string | `CASH_IN`, `CASH_OUT`, `DEBIT`, `PAYMENT`, `TRANSFER` |
| `amount` | float | Transaction amount |
| `nameOrig` | string | Origin account id (`C`-prefixed = customer) |
| `oldbalanceOrg` | float | Origin balance before the transaction |
| `newbalanceOrig` | float | Origin balance after the transaction |
| `nameDest` | string | Destination account id (`C` = customer, `M` = merchant) |
| `oldbalanceDest` | float | Destination balance before the transaction (always 0 for merchant destinations — balances are never tracked for merchants, matching real PaySim) |
| `newbalanceDest` | float | Destination balance after the transaction (same merchant caveat) |
| `isFraud` | int | Ground-truth fraud label (1 = part of a simulated TRANSFER→CASH_OUT laundering episode) |
| `isFlaggedFraud` | int | Naive rule replicated from PaySim: 1 if `type == TRANSFER` and `amount > 200,000` |

**Known label-leakage caveat (intentionally reproduced):** fraud episodes zero out the destination balance on the
laundering leg, mirroring a well-documented PaySim quirk where `isFraud` correlates with unreported destination
balances. The detection engine's feature engineering (`detection/features/engineer_features.py`) deliberately avoids
raw balance columns as model inputs for this reason — see ADR-0003.

Regenerate with: `python scripts/generate_paysim_sample.py` (seeded, fully reproducible).
